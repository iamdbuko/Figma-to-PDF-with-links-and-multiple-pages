# v9.0.1 — Heavy-file export fixes

Prepared on November 13, 2026. Publication status is recorded in the GitHub release and Figma Community version history.

- Prevents unused native image resources from inflating exported PDFs, including when Original quality is selected.
- Releases rejected native PDF data before retrying a page as a raster image.
- Fixes shared transparency-mask resources preventing unrelated images from being reduced to the selected DPI.
- Keeps image-resolution warnings visible when an export fails and identifies the affected page and part.
- Clarifies that JPEG applies to RGB rasterized pages and vector fallbacks; it does not recompress images inside accepted vector pages.

The interface, defaults, color options and existing size safeguards are unchanged. Content that cannot safely be optimized is preserved with a warning. Very large individual pages or output files may still require lower resolution, smaller parts or a simpler source frame.

Validation includes **294 passing automated tests**, a 77-page synthetic reproduction exported at Original, 72 DPI and 36 DPI, and a six-part export. Every successful large test preserved 385 external and 154 internal links. An eight-frame native Figma Desktop export also passed page-size, exact-link and visual checks. These tests do not establish the cause of an unavailable user's file or guarantee every design and PDF viewer.

See the [investigation and reproduction evidence](../HEAVY-NATIVE-EXPORTS.md). Keep split PDFs together with their original filenames; navigation between parts still depends on the PDF viewer. CMYK remains a beta feature and is not PDF/X.
