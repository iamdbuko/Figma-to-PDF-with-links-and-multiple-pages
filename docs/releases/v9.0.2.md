# v9.0.2 — Prevent high-DPI vector image growth

Prepared on November 13, 2026. Candidate only: a fresh native Figma check and publication remain pending. Production remains v9.0.1 / Figma Community Version 10.

- Fixes an RGB Vector export case where lowering embedded JPEG resolution could greatly increase PDF data and trigger the retained-data allowance, including at 300 DPI.
- Keeps the original JPEG and its transparency mask when the replacement would take more encoded space, preserving the original image quality and color profile. A visible warning explains that the image stayed at its original resolution.
- Continues normal downsizing when the replacement is smaller or equal in size. Shared transparency masks are counted conservatively so their bytes are not treated as removable while another object still needs them.

This safeguard applies to supported JPEG images inside RGB Vector exports. Original quality, Rasterized exports, CMYK conversion, non-JPEG processing, links, interface defaults and size safeguards keep their existing behavior. A retained JPEG can remain above the selected DPI; this change does not add detail, introduce lossy JPEG recompression or remove memory limits.

Validation includes **304 passing automated tests**, including actual saved-PDF assertions for the keep-original and downsize branches, exact link rectangles/targets, masks, ICC profiles, equality, shared resources, cancellation and RGB/CMYK separation. The actual built UI also exported 148 saved native report pages into a 116,682,827-byte single PDF at 300 DPI, below the unchanged 128 MiB allowance. All 301 link targets and geometry were preserved within negligible replay-coordinate roundoff; vectors, text and ICC data were unchanged, and all pages passed rendered comparison. This replay does not exercise fresh Figma rendering or its backend link scanner. Scoped report validation is recorded in the [investigation and evidence](../DPI-SIZE-GUARD.md) and [validation record](v9.0.2-validation.json).
